# RT-11 closure — the "two 502 subdomains" gate

- **Date:** 2026-10-04. **Scope:** close the v9 residual "fix or delete the 2 subdomains
  returning 502 (blocks HSTS preload)" with runtime evidence, or state honestly that it cannot
  be closed.

## Evidence (all re-measured 2026-10-04, anonymous, TLS on)

| Host                     | Result                                       |
| ------------------------ | -------------------------------------------- |
| `sgps.blueskyzlabs.com`  | **does not resolve** (`curl` exit, HTTP 000) |
| `atlas.blueskyzlabs.com` | **does not resolve** (HTTP 000)              |
| `sotro.blueskyzlabs.com` | 200 (the live product site)                  |
| `sotam.blueskyzlabs.com` | 200 → Logto OIDC (the live product app)      |

The v8 plan (`docs/superpowers/plans/2026-10-01-website-elevation-v8.md:769`) names the pair:
"HSTS is blocked by the 502 `sgps`/`atlas` subdomains." Both names were re-probed today; neither
resolves, so neither can return 502. This agrees with the v10 redteam record
(`docs/evidence/2026-10-03-v10-multidimensional-redteam.md`, RT-11): among 16 probed subdomains,
only `sotro` and `sotam` resolve and **none returns 502**.

## Disposition

**CLOSED** — the broken-subdomain precondition for HSTS preload is satisfied because the
subdomains no longer exist. The gate's purpose was to stop a broken host from being sealed into
`includeSubDomains` preload lists; with both names unresolvable, that risk is gone.

Residuals kept explicit:

- The HSTS `preload` directive itself is **not** added here — that remains its own deliberate
  decision (preload is effectively irreversible; it is not required for go-live).
- The probe list is a named subset plus the redteam's 16-name enumeration, not full zone data.
  If the Owner knows of other hostnames that answered 502 historically, this closure should be
  re-opened with those names.
