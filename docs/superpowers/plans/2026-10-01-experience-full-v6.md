## 3. Product Experience DNA

**One sentence (working DNA, adapted from audit §1.2; Owner ratification is a feedback checkpoint, not a blocker):**

> Calm, verifiable software made for everyday Vietnamese life and work: it shows what it does, says plainly what is not ready, and never pressures.

**Principles (product/user terms, no cultural theme names):**

1. **Show the product first.** A visitor sees a real product, a real screen and one next action before any claim about the company. (Serves E-02, E-03, E-06.)
2. **Say less, once.** One positioning line, one slogan, one primary action per view, status stated once per surface. Repetition is removed before anything is added. (Serves E-05, E-11, E-24.)
3. **Honesty is designed, not disclaimed.** "In development", "synthetic data", "not a store release" appear as composed, confident states, not as apologetic captions and duplicate links. (Serves E-03, E-12.)
4. **Proof on demand.** Verification is the differentiator; it is one deliberate step away (`/verify`) in plain language, revealed in layers, never page furniture. (Serves E-13.)
5. **Precision with patience.** Geometry is exact and motion is patient: things assemble, settle and rest. No perpetual loops, no ambient decoration. (Serves E-17, E-19, E-21.)

**Trust/safety/privacy constraints:** no cookies, no analytics transmission, no remote AI, no invented facts/metrics/testimonials/emails/legal prose/screenshots; Marketing is not a payment authority.
**Accessibility/platform:** WCAG 2.2 AA; 44 px targets; no overflow 320–1440 px and at 200 % text; static/no-JS and reduced-motion independently meet the content/action contract; four locales (`vi`, `en`, `zh`, `zh-hant`), light and dark.
**Default cultural expression:** `C1` site-wide (latent intelligence, Vietnamese identity carried by content and typography care). **Allowed visible signature:** `C2` at flagship/hero moments only, via the Reveal prototype (see §7), labelled `VALIDATE` prototype.
**Design-intelligence mapping (BPXS default):** visual field/precision = Chu Đậu = **visible** (construction-line geometry, hairline precision); temporal depth/disclosure = Sơn Mài = **visible** (layered revelation) — together they are one signature, "Reveal"; information structure/rhythm = Đông Sơn, system architecture/adaptation = Tre, signature/emergence = Sen = **latent only**. `Contemporary Vietnam` is a research/validation lens (native review, Human E4), not a theme.
**Forbidden regressions:** lacquer/gold/red-black skins; ceramic blue-and-white presented as uniquely Vietnamese; any name of a cultural source used as a token/theme/class; more than one signature cue per composition; ambient looping motion; a hero element that waits on animation; identity art posing as a product screenshot; any warm-palette bridge (declined 2026-09-30).

**Cultural provenance rule (Gate F).** Each visible cue carries a provenance note in the S7 evidence file: observed property (layering, translucency, precise incised/drawn geometry) versus documented meaning versus BlueSkyz interpretation; no AI-generated motif is treated as heritage evidence; the cue is structural (layers, reveal order, line precision) and uses no lacquer colours or textures.

## 7. Motion system specification

**Signature: "Reveal" (Owner-chosen, VALIDATE prototype).** Patient layered revelation (Sơn Mài as a structural principle: layers, translucency, order of disclosure) with construction-line precision (Chu Đậu as a drawing discipline: exact strokes, exact joins). No lacquer colours or textures. One grammar, three appearances:

1. **Hero mark assembly:** the sail mark is drawn from construction lines (SVG strokes, `stroke-dashoffset` from 100 % to 0 %), then the prismatic fill layers fade in back-to-front, then it rests. Total ≤ 1 100 ms after start.
2. **Flagship frame reveal:** device frame plane, screen plane, then caption plane enter in that order on first scroll into view. Once per page load; never re-triggered on scroll direction change.
3. **Trust disclosure (`/verify`):** each disclosure layer opens with the same plane-by-plane order (claim plane → evidence plane → source plane), replacing node-code furniture with an ordered reveal.

**Cardinality rule:** at most one signature appearance dominates a composition; appearances 1 and 2 do not animate in the same viewport at the same time. No signature motion on Privacy, Support, Contact, 404 or the gateway.

**Implementation constraints (hard):**

- CSS and inline SVG only. Client JS for motion ≤ 2 KB Brotli and limited to one `IntersectionObserver` toggling a single `data-revealed` attribute; the site-wide client JS budget remains 120 000 B and is not spent.
- No WebGL, no canvas, no video, no Lottie, no third-party animation library. `animation-timeline: view()` may be used as progressive enhancement inside `@supports`, with the `IntersectionObserver` path as the baseline.
- Animate only `transform`, `opacity`, `stroke-dashoffset` and `clip-path`; no layout-affecting properties; no `will-change` outside the animating window; no infinite loops (delete dead `hero-glow-pulse`).
- Never `backdrop-filter` on content surfaces (ADR 0012 keeps blur to the shell).

**Tokens (defined in the token layer, names are functional, never cultural):**

| Token                | Value                           | Use                                                                   |
| -------------------- | ------------------------------- | --------------------------------------------------------------------- |
| `--motion-instant`   | 90 ms                           | Hover/press feedback                                                  |
| `--motion-quick`     | 180 ms                          | Small state changes                                                   |
| `--motion-base`      | 320 ms                          | Plane fade/translate                                                  |
| `--motion-reveal`    | 560 ms                          | Frame planes                                                          |
| `--motion-draw`      | 900 ms                          | Construction-line draw (hero mark, ≤ 1 100 ms total with layer fades) |
| `--motion-stagger`   | 70 ms per plane, max 4 planes   | Reveal order                                                          |
| `--ease-standard`    | `cubic-bezier(0.2, 0, 0, 1)`    | Default                                                               |
| `--ease-emphasized`  | `cubic-bezier(0.16, 1, 0.3, 1)` | Plane settle                                                          |
| `--ease-linear-draw` | `cubic-bezier(0.4, 0, 0.2, 1)`  | Stroke draw                                                           |

Exact values are `VALIDATE`: they are the starting point of the prototype and may be tuned in S7 with recorded before/after evidence; a change is recorded in the slice PR, not silently.

**LCP rule (hard, guarded):** the LCP element on every route is static and paints without waiting on animation, script or font swap of the display face. Concretely: the hero's LCP candidate (text block, or the static capture image with explicit `width`/`height`, `fetchpriority="high"`, preloaded) is rendered at final opacity/position in the initial HTML/CSS; the assembling mark is a non-LCP decorative overlay that starts **after** the first paint and never sets the LCP candidate to `opacity: 0`, `visibility: hidden` or off-position. Initial state hidden-until-animated is forbidden for any element that can be the LCP candidate. Guard: a build test fails if any element tagged as an LCP candidate (or `[data-lcp]`) has an animation/transition on `opacity`, `transform` or `visibility` in its initial state, with a mutation negative proof; Lighthouse (S9 and per-slice) confirms the LCP node.

**Reduced-motion equivalent:** under `prefers-reduced-motion: reduce`, every appearance renders its **final resting state immediately** (mark fully drawn, planes in place, disclosure layers open/close without transition); no fades, no translate, no stroke draw. No information or action is available only through motion.

**No-JS equivalent:** without JavaScript, the baseline is the final resting state (the `data-revealed` attribute is present in the served HTML or the CSS default is the final state; the observer only adds the pre-reveal state after it runs, and only if motion is allowed and the element is below the fold). CSS-only fallback: `@supports (animation-timeline: view())` drives the reveal without JS; browsers with neither show the final state. `/verify` disclosures use native `<details>` so no layer requires JS.

**Other motion contract points:** forced-colors mode shows final state and strokes in system colours; print shows final state; motion never conveys status (status stays in text); no motion starts in the first 100 ms of paint to protect INP and CLS; CLS contribution of motion is zero by construction (no layout properties animated, reserved dimensions). Each appearance ships a unit/E2E test for the three states (motion, reduced, no-JS) and a negative proof (removing the reduced-motion rule turns the test RED).

## 8. Typography system

**Faces.**

- Text: Inter Variable (existing, self-hosted; latin + vietnamese).
- Display: one second face, self-hosted, SIL OFL, WOFF2, subsets latin + latin-ext + vietnamese (approved 2026-09-30). **Candidate selection is a slice task (S4)**, not decided here: the S4 PR records at least two OFL candidates, licence file, Vietnamese diacritic stacking check (`Ệ`, `Ữ`, `Ẳ`, `ộ`), numeral style and file size, and picks one with a rendered comparison. No name is assumed in this plan; whichever face is chosen must render Vietnamese with real glyphs, not synthesized diacritics. CJK (`zh`, `zh-hant`) falls back to system CJK stacks for display and text (no CJK webfont; approved constraint).
- Mono: existing system/mono stack for ordinals only.

**Roles.** Display face: H1 and at most one H2 per surface, large numerals, the hero statement; never body copy, never below 28 px, never in CJK. Inter: body, UI, eyebrows, buttons, captions, H3+. The second face is **not** used for eyebrows, chips or small caps.

**Fluid scale** (`clamp()`, mobile 390 px → desktop 1440 px; starting values, `VALIDATE` in S4 with screenshots):

| Step | Role            | Size                                       | Line-height | Tracking                  |
| ---- | --------------- | ------------------------------------------ | ----------- | ------------------------- |
| d1   | Display (hero)  | `clamp(2.5rem, 1.6rem + 3.6vw, 4.5rem)`    | 1.05–1.1    | -0.02em                   |
| d2   | Display (H2)    | `clamp(1.75rem, 1.3rem + 1.8vw, 2.75rem)`  | 1.15        | -0.015em                  |
| t1   | H3              | `clamp(1.25rem, 1.15rem + 0.4vw, 1.5rem)`  | 1.3         | -0.01em                   |
| b1   | Body            | `1rem`–`1.125rem`                          | 1.6         | 0                         |
| b2   | Secondary       | `0.9375rem`                                | 1.5         | 0                         |
| c1   | Caption/eyebrow | `0.8125rem` (13 px floor; nothing < 12 px) | 1.4         | 0.04em caps only in Latin |

The audit's 72/79 px H1 shrinks to a measured, content-carrying hero, and the "large type without content" pattern (E-10) is banned: a display-size text must sit directly above content it introduces.

**Rhythm and measure.** One vertical rhythm (8 px base; section gaps from a 4-step scale). Body measure 60–72 ch (Latin/VI), 28–38 full-width characters per line (CJK). Consistent leading per step across locales unless a locale override is listed below.

**Locale tuning.**

- **CJK (`zh`, `zh-hant`):** `line-break: strict`; `word-break: auto-phrase` (progressive enhancement, falls back to `normal`, never `break-all`); `text-wrap: pretty` for body, `balance` for headings; `hanging-punctuation` where supported; line-height 1.7 body; no letter-spacing on CJK; no italic; no display face; trim the redundant zh-hant "開發範圍：" prefix under a heading of the same words (copy trim, feedback checkpoint for native review).
- **Vietnamese:** line-height +0.05 over Latin for stacked diacritics; `text-wrap: balance` on headings to avoid "Trí tuệ. Nâng / tầm." style breaks; display face must be verified on `Ệ`/`Ữ` stacks at d1.
- **Latin/English:** `text-wrap: balance` headings, `pretty` body; hyphenation off for headings.

**Font loading.** `font-display: swap` with metric-matched fallback (`size-adjust`, `ascent-override`, `descent-override`, `line-gap-override`) so swap causes CLS 0; preload at most one font file (the display face subset used by the LCP heading only if the LCP is text; otherwise none); `unicode-range` subsets so `vi` loads only what it needs. **Budget:** total font transfer ≤ 90 KB WOFF2 across text + display on any route (current 88 KB is already at the cap, so adding a face requires subsetting/variable-axis trimming; S4 must show measured bytes), and the LCP element must not depend on the display face (fallback shows immediately; swap must not change layout beyond the metric-matched fallback).
