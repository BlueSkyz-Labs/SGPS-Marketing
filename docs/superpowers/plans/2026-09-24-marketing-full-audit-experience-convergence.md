## Findings and exact remediation

### H-01: Dossier can publish a claim after its provenance becomes unknown

Priority: P1. This is an observed conditional gap, not a proven live exploit.

In src/lib/dossier.ts, the claims branch checks that the claim exists but
builds an entry even when getPublicProvenance returns null or unknown. Current
tests reject missing identifiers but do not model an existing claim that
loses valid independent evidence. A later registry change could show its
statement without a trustworthy source chain.

Implement a negative fixture or dependency seam in
tests/architecture/c4-dossier-provenance.test.mjs. Prove RED for a real claim
with refused provenance. Make the smallest fix in src/lib/dossier.ts: reject
the claim with a reason, produce complete=false and retain valid canonical
labels, references and authored freshness. Cover EN, VI, zh, print and no-JS.
If the negative fixture disproves the hypothesis, record that and avoid an
unnecessary code change.

### H-02: Live work router is behind C4 implementation

Priority: P1. Inspect #224 latest head and reconcile against current main,
open PRs and actual source evidence. Keep one active IN_PROGRESS wave. Preserve
owner gates and existing evidence paths. Make stale PR references detectable
and prevent a new agent from treating a merged task as active. No second
registry, plan router or unsupported merge-completion claim.

### H-03: Concurrent C4 branches can overwrite each other

Priority: P1. Review changed files, ancestry, conflicts and exact-head CI.
